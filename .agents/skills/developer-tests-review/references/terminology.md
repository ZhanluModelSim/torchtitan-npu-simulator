# 审查术语对照

审查报告优先使用右侧术语。代码标识、CI 变量和上游固定名称可以保留原文，并在首次出现时补充中文说明。

| 不推荐用语 | 统一用语 | 使用说明 |
| --- | --- | --- |
| 最小动作 | 合入前置条件 / 必要措施 | 写清必须新增、修改或确认的测试内容 |
| 决定性原因 | 阻塞问题 / 核心缺陷 | 只有影响合入建议时使用“阻塞问题” |
| 静态发现 | 静态审查结果 / 代码阅读结果 | 表示通过阅读代码得到的观察 |
| 代码事实 | 实际代码逻辑 / 当前实现表现 | 描述代码当前做什么 |
| 建议改法 | 修改建议 / 推荐检验方案 | 说明如何补齐或重写测试 |
| 顶层目的 | 变更目标 / 核心设计意图 | 描述 PR 要实现的用户或训练结果 |
| 候选提交 | 待审查提交 / 当前变更集 | 描述本次被审查的提交 |
| 候选提交的父提交 | 父提交 / 基线提交 | 描述提交关系 |
| 生产差异 | 生产代码变更 | 指非测试的产品源码变更 |
| Runner 静态可达 | CI 执行路径覆盖 / 测试自动发现 | 描述 CI 是否会发现和运行测试 |
| Matrix visualization | 测试组合矩阵 / 矩阵投影 | 描述模型、并行、替换实现和编译组合 |
| 短步数 golden | 固定步数基准值 / 短迭代对照数据 | 首次出现可写“基准记录（golden）” |
| No-ST | 无需系统测试覆盖 | 只在判断表中使用，必须说明负责的证据层 |
| ADAPT | 适配修改 | 已有 ST 路径正确，只需补条件、启用检查或基准值 |
| DEFER | 延后处理 | 需要 ST 但不适合当前设备或执行阶段 |
| carrier | 现有代表测试 | 指可以承载本次变更场景的已有 ST |
| activation | 启用检查 | 直接检查目标替换实现、算子或编译路径确实被使用 |
| evidence | 直接检查 / 测试依据 | 指测试代码中可定位的准备、调用和断言 |
| semantic coverage | 正向功能覆盖 | 指 PR 正向功能与测试直接检查的对应关系 |
| verdict | 审查结论 / 合入建议 | 面向 reviewer 的最终判断 |
| happy path | 正向功能 / 正常支持路径 | 描述正常输入和受支持配置，不扩展未知反例 |
| handoff / contract | 参数传递 / 接口约束 | 直接写明谁把什么对象传给谁 |
| changed owner | 受影响生产模块 | 写具体文件和使用位置 |
| companion evidence | 配套检查 | 指 ST 不能替代的算子数值、断点续训或性能检查 |
