# 文档验证

在撰写仓库首页、操作指南、可执行示例或审阅现有文档时使用本检查清单。简单措辞调整无需执行全部检查。

## 验证状态

| 状态 | 含义 |
|------|------|
| `passed` | 已完成静态核对或实际执行，结果符合文档描述 |
| `failed` | 核对或执行失败，文档需要修正 |
| `skipped` | 环境缺失或用户明确要求跳过，已完成可行的静态检查 |
| `not-run` | 命令成本高、风险大或超出任务范围，未执行 |

不要把静态检查写成运行通过。`skipped` 和 `not-run` 必须记录原因及仍未确认的结论。

## 正确性

- 对照实际仓库核对文件路径、目录树、模块导入、配置键和环境变量。
- 对照源码与测试核对能力清单、支持矩阵、互斥关系和已知限制。
- 对照 `pyproject.toml`、脚本和运行环境核对依赖、版本与启动方式。
- 检查示例引用的文件、配置、权重格式和预期输出是否存在。
- 检查当前状态、计划和历史结果是否混写。
- 解析每个改动过的相对链接，确认目标文件存在；带锚点的链接还要确认目标标题存在。

## 易理解性

- 首段是否说明用途、目标读者、适用条件和主要限制。
- README 是否提供最短可行入口，并把长篇原理链接到独立文档。
- 操作指南是否按「前置条件 → 输入 → 命令 → 预期输出 → 判读 → 常见失败」展开。
- 标题是否构成连续叙事，术语是否前后一致，是否存在重复或突然跳转。
- 限制是否靠近对应能力，而不是集中藏在文末。

## 规范性

- 检查标题层级、代码块语言、表格列义和中英文留白。
- 保持代码、路径、配置键和机器可读标识符原样。
- 检查相对链接，不引入无必要的绝对本地路径。
- 目标文档涉及分发、安装或安全说明时，再核对许可证和安全声明；普通功能文档无需机械添加这些章节。

## 命令验证

1. 从目标文档提取原始命令、工作目录、环境变量和输入文件。
2. 先检查依赖、NPU、CANN/HCCL 和数据是否就绪。
3. 仅执行安全、范围明确、成本可控的命令。训练、权重转换、大规模编译或其他高成本操作，只有用户明确要求时才执行。
4. 记录命令、状态、关键输出和失败原因。不要改用另一条更容易成功的命令代替原命令。
5. 命令失败时先判断是文档错误、环境缺失还是实现问题，再决定修改文档或报告阻塞。

## 审阅结果

审阅文档时按以下优先级报告问题：

- 阻塞：命令错误、导入路径错误、能力声明与实现冲突，或遗漏会导致数据损坏的限制。
- 重要：支持范围、版本、环境、互斥关系或预期输出不完整，可能导致误用。
- 建议：结构、导航、术语或排版问题，不影响功能使用。

每项问题包含文件位置、直接证据、影响和最小修正建议。没有证据时标记为待确认，不写成确定结论。
